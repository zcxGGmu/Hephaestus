System-level Agent Product 面向真实执行的智能体产品层

Build a product surface around agent execution, not just chat output. 把 Agent 执行流做成产品界面，而不只是一个聊天输出框。

Hephaestus turns a generalist agent stack into a coherent product: threads, tool calls, background workers, persistent state, and sandbox execution all connected through one system narrative. Hephaestus 把通用智能体栈组织成一个完整产品：线程、工具调用、后台 Worker、持久化状态和沙箱执行被统一收进同一个系统叙事中。

This is not about building another AI chat homepage. It is about presenting context, execution, tools, persistence, and UX as one understandable operating surface. 这不是“再做一个 AI 聊天首页”，而是把上下文、执行、工具、状态落库和产品体验真正组合成一个可部署、可演化、可协作的操作界面。

Execution Flow 从用户意图到工具执行的完整路径

Hephaestus is built around observable execution.

Hephaestus 的核心不是“回答”，而是可观察的执行。

What matters is not only that an agent can act, but that the system makes the process understandable: queued runs, tool use, streaming updates, and persisted thread state.

关键不只是 Agent 能不能行动，而是系统是否让整个过程清晰可见：任务排队、工具调用、流式更新、线程状态和持久化结果都应该被用户理解。

01

User Intent

User starts a task 用户发起任务

A user creates or continues a thread from the frontend and sends a structured request.

用户在前端创建或继续一个线程，并提交结构化任务请求。

02

API Orchestration

Backend prepares context 后端接管上下文

The backend persists thread context, prepares run records, and coordinates execution setup.

后端持久化线程上下文，创建运行记录，并协调后续执行准备工作。

03

Queued Execution

Task enters the queue 任务进入队列

Redis and Dramatiq hand the task to a worker so long-running jobs do not block the request cycle.

Redis 与 Dramatiq 把任务移交给 Worker，避免长任务阻塞请求流程。

04

Agent Runtime

Agent executes with tools Agent 实际执行

The runtime uses tools, files, shell, browser, or sandbox-backed actions while preserving intermediate state.

运行时开始调用工具、文件、Shell、浏览器或沙箱能力，同时保留中间状态。

05

Streaming Return

Results stream back 结果流式返回

Structured updates are pushed back to the UI so users can observe reasoning, tools, and outputs in real time.

结构化更新被持续推回 UI，用户可以实时观察推理、工具和最终输出。

Why separate the product app from the website? 为什么要把产品应用和官网拆开？

The product app and the website serve different goals. The app is an authenticated operational surface, while the website is a public narrative and entry point.

产品应用和官网承担的是不同目标。前者是登录后的真实操作界面，后者是对外叙事和入口页面。

Is Hephaestus only a chat interface? Hephaestus 只是一个聊天界面吗？

No. The system is structured around threads, tool execution, background workers, persistence, and sandbox-backed actions. Chat is only one layer.

不是。系统围绕线程、工具执行、后台 Worker、持久化和沙箱动作组织起来，对话只是其中一个交互层。

Why emphasize Redis, workers, and persistence on the website? 为什么官网要强调 Redis、Worker 和持久化？

Because those layers determine whether the platform can handle real tasks. The website should make those execution guarantees legible.

因为这些层决定了平台是否真的能承载真实任务。官网应该把这些执行保证讲清楚，而不是只说“它很智能”。

Can this site be deployed independently of the product app? 这个官网可以和产品应用独立部署吗？

Yes. The `website/` directory is static and deploys well on GitHub Pages or any static host, while the product app remains in `frontend/`.

可以。`website/` 是纯静态目录，适合 GitHub Pages 或任意静态托管平台，而真实产品应用继续保留在 `frontend/`。
