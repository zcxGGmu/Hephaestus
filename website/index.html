Product Positioning 和普通聊天式产品的差异

Hephaestus is closer to an execution platform than a chatbot shell.

The website should help visitors immediately understand what makes the system different: it is not only about model response quality, but about product structure, execution flow, and tool visibility.

Chat-first tools

Prompt in, answer out.

  • Conversation is the whole surface
  • Execution is hidden or abstracted away
  • Tool usage often collapses into plain text
  • State is shallow or short-lived
Hephaestus

Intent in, systemized execution out.

  • Projects, threads, tools, runs, and state all have product surfaces
  • Async execution is a first-class design constraint
  • Tool output is rendered as structured UI, not only text
  • Persistent backend state makes tasks resumable and inspectable

Local-first

For teams that want to run the stack under their own control and keep credentials, workflows, and execution surfaces closer to the edge.

Private deployment

Suitable for internal environments where product teams need stronger ownership over data flow, runtime coordination, and system boundaries.

Public product surface

The landing website can stay static and fast, while the product application evolves separately as a richer operational interface.

cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Configure services 配置数据库与 Redis 
Copy-Item .env.example .env
python scripts/01_setup_database.py
python scripts/02_setup_redis.py
python scripts/03_init_hephaestus_table.py
Run the system 启动前后端与 Worker 
# terminal 1
python api.py

# terminal 2
dramatiq run_agent_background

# terminal 3
cd ../frontend
npm install
npm run dev
FAQ 把最常见的问题提前讲清楚

Questions a technical team will ask before adopting the platform.

A stronger product website should answer architecture and deployment questions directly, especially when the system sits between product UX and agent infrastructure.

Why separate the product app from the website?

The product app and the marketing site serve different goals. The app is an authenticated operational surface, while the website is a public narrative and entry point.

Is Hephaestus only a chat interface?

No. The system is structured around threads, tool execution, background workers, persistence, and sandbox-backed actions. Chat is only one interaction layer.

Why emphasize Redis, workers, and persistence on the website?

Because those layers determine whether the product can handle real tasks. The website should make those execution guarantees legible instead of hiding them behind generic AI messaging.

Can this site be deployed independently of the product app?

Yes. The `website/` directory is static and can be deployed to GitHub Pages or any static host, while the product application continues to live in `frontend/`.
